# 12 - Anchors, Snap và Attach

Tài liệu này mô tả cách hệ thống hỗ trợ user **đưa các component lại gần nhau, nhận biết part gần nhất, snap đúng điểm và lưu quan hệ gắn kết** mà không tạo lại Three.js parent-child hierarchy.

## 1. Ba khái niệm khác nhau

- **Anchor** thuộc Manifest: mô tả một điểm/mặt/trục kết nối hợp lệ của component.
- **Snap** là tương tác trong Editor: khi source anchor đến đủ gần target anchor tương thích, hệ thống căn source vào target.
- **Attachment** thuộc Configuration: lưu việc source component đang được gắn logic vào target component.

Không dùng `object.add(child)` hoặc re-parent mesh để biểu diễn attachment. Runtime component vẫn là sibling độc lập trong Editor Component Layer.

## 2. Manifest tự tạo anchor như thế nào

Với asset mới, mỗi detected component được tạo 7 geometry anchor mặc định:

- Center
- Left
- Right
- Top
- Bottom
- Front
- Back

Các anchor này có `connectionType = GENERIC`, `compatibleTypes = [GENERIC]`, `autoGenerated = true` và `snapEnabled = true`.

Mục tiêu của anchor mặc định là làm snap geometry hoạt động ngay. Chúng **không khẳng định semantic** rằng một điểm chắc chắn là wing root, engine mount, leg socket...

## 3. Semantic anchor trong Asset Preparation

Khi chọn component ở Asset Preparation, Anchor Setup cho phép chỉnh:

- `Name`
- `Kind`: POINT / PLANE / AXIS / BOUNDS_CENTER
- `Connection type`
- `Accepts types`
- Position X/Y/Z theo mm
- Rotation X/Y/Z theo degree
- Snap enabled
- Align rotation when snapping
- Tags

Ví dụ:

```text
Left Wing / Wing Root
connectionType = WING_ROOT
compatibleTypes = [WING_MOUNT]

Fuselage / Left Wing Mount
connectionType = WING_MOUNT
compatibleTypes = [WING_ROOT]
```

Snap semantic chỉ hợp lệ khi hai phía chấp nhận loại của nhau.

## 4. Nearest-part indicator

Trong Editor, khi `Move` một part và Snap đang ON:

1. Tính tất cả source anchors của part đang kéo.
2. So với anchors của các part visible, không deleted khác.
3. Chọn cặp anchor có khoảng cách nhỏ nhất.
4. Nếu part đủ gần vùng quan sát, target component được highlight bằng indicator riêng.
5. UI hiển thị target component, source anchor → target anchor và khoảng cách hiện tại theo mm.

Nearest indicator vẫn có thể xuất hiện khi anchor types không tương thích. Trong trường hợp này UI ghi rõ incompatible và **không magnetic snap**.

## 5. Magnetic snap

Threshold dùng screen-space thay vì fixed world distance:

- nearest indicator: khoảng 96 px
- magnetic snap: khoảng 18 px

Nhờ vậy cảm giác thao tác nhất quán khi dùng model rất lớn như aircraft hoặc model nhỏ như furniture.

Khi candidate compatible vào snap threshold, indicator chuyển thành `READY TO SNAP`. Khi user thả chuột:

1. source anchor được đặt trùng target anchor;
2. nếu cả hai anchor bật `alignRotation`, orientation cũng được căn;
3. editor dispatch structured `SET_POSITION` / `SET_ROTATION`;
4. cuối transaction dispatch `ATTACH_COMPONENT`;
5. Undo có thể hoàn tác transaction như một chỉnh sửa editor.

## 6. Attach / Detach

Attachment được serialize trong Configuration:

```json
{
  "id": "att_left-wing_wing-root_body_left-wing-mount",
  "sourceComponentId": "left-wing",
  "sourceAnchorId": "wing-root",
  "targetComponentId": "body",
  "targetAnchorId": "left-wing-mount",
  "createdBy": "SNAP"
}
```

Hiện tại target **translation** được truyền tới attached source thông qua editor-core. Việc follow này là mutation business state, không phải transform inheritance của Three.js.

Nếu user trực tiếp Move / Rotate / Resize / Replace source component đang attached, attachment cũ bị bỏ vì hành động đó được hiểu là user đang cố tình tách part ra. Có thể snap lại để tạo attachment mới.

Delete hoặc Reset component cũng dọn attachment liên quan.

## 7. Shortcut

- `S`: bật/tắt Snap.
- `L`: bật/tắt component label.

Shortcut không chạy khi focus nằm trong input, textarea, select hoặc contenteditable.

## 8. Backward compatibility

Manifest cũ không có `anchors` và Configuration cũ không có `attachments` vẫn parse được.

Khi mở asset cũ chưa có saved anchors, viewer có thể tạo auto anchor draft dựa trên geometry hiện tại. Sau khi review, hãy Save Manifest để persist anchor metadata.

## 9. File chính

- `packages/model-schema/src/index.ts` — AnchorDefinition và Attachment schema.
- `packages/action-engine/src/index.ts` — ATTACH_COMPONENT / DETACH_COMPONENT.
- `packages/editor-core/src/index.ts` — validation, persistence và attached translation.
- `apps/web/lib/anchor-runtime.ts` — auto anchor + world-space snap math.
- `apps/web/lib/snap.ts` — compatibility helper.
- `apps/web/lib/snap-store.ts` — transient snap/indicator UI state.
- `apps/web/components/ModelViewport.tsx` — nearest-part indicator và magnetic snap.
- `apps/web/components/SnapViewportHud.tsx` — Anchor Setup, Snap/Labels status và Detach.

## 10. Quy tắc mở rộng

Khi bổ sung connection type mới, ưu tiên semantic rõ ràng và reciprocal compatibility, ví dụ:

```text
WING_ROOT ↔ WING_MOUNT
ENGINE_PYLON ↔ ENGINE_MOUNT
LEG_TOP ↔ LEG_SOCKET
HANDLE_BASE ↔ HANDLE_MOUNT
DRAWER_RAIL ↔ DRAWER_SOCKET
```

Không đưa semantic guess chưa xác nhận thành luật bắt buộc. Auto geometry anchors là draft; semantic data nên được review trong Asset Preparation trước khi Save Manifest.
